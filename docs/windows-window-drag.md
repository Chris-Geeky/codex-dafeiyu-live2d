# Windows 主窗口拖动跳动

在部分 Windows 环境中，原生宠物窗口显示时，拖动 Codex 主窗口会让位置来回跳动。当前有两个可用绕法：将宠物放到屏幕最左侧，或移动主窗口前暂时隐藏宠物。

## v0.5.2 按下触发与移入触发

“播放与窗口”卡片中开启“拖窗兼容模式”和“提前避让”，再选择触发方式：

- **按下时（推荐，默认方式）：** 鼠标在 Codex 顶部／边框按下才收起，按住拖动时保持收起，松手后恢复。单纯移入不会隐藏；从正文选字再拖到顶部也不会触发按下避让。通过短周期查询鼠标状态提前识别，不拦截或延迟鼠标消息。
- **移入时：** 沿用 v0.5.1 的悬停避让，移入顶部／边框即收起，移开约 200 毫秒后恢复，停在顶部时持续收起。准备时间更长，但经过顶部菜单也会隐藏。

提前避让开关默认关闭；开启后默认选按下触发。可随时关闭或切换，两项偏好保存在本机。原生移动通知仍作为恢复与收起的备用路径。2026-10-31 本机用户实测：“快速拖动仍然会闪，慢一点就不会闪”。按下后完成收起仍需要时间，该模式尚未消除快速拖动的起步闪烁；用户目前保留按下模式，鼠标经过时保持显示。其他电脑仍需验证，不承诺全环境修复。

## v0.5.1 移入避让（已实测）

v0.5.1 增加了可关闭的顶部／边框移入避让。2026-10-31 本机用户实测反馈：“开头也不闪了，能自动恢复”。该结果限此电脑和该触发方式。用户随后希望鼠标经过时保持宠物显示，因此 v0.5.2 增加了按下触发，并保留移入方式供选择。

鼠标进入 Codex 顶部或缩放边框时提前收起原来可见的宠物，离开约 200 毫秒后恢复。拖动过程中保持收起；松手时鼠标若仍在顶部，移开后才恢复。短暂跨过边缘不会反复收起／显示。关闭提前避让会回到普通拖窗模式；关闭兼容模式或正常退出助手时，会恢复由助手暂时收起的宠物。原本隐藏的宠物保持隐藏。

实现使用仅针对已连接 Codex 进程的窗口查询、限时原生命中检测和现有收起流程；未添加全局鼠标钩子或修改 Codex 文件。顶部自定义标题区包含距顶部约 48 个逻辑像素，因此点击顶部菜单也可能暂时收起宠物。该选项为异步关闭鼠标转发留出时间；极快地移入并拖动仍可能来不及，不能承诺彻底消除闪烁。实际拖动效果需要用户验收。

参考：[Windows 命中检测](https://learn.microsoft.com/en-us/windows/win32/inputdev/wm-nchittest)、[限时窗口查询](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-sendmessagetimeoutw)。

## v0.5.0 普通拖窗兼容模式

v0.5.0 的原生助手提供可关闭的“拖窗兼容模式”，将收起／恢复流程自动化。它监听当前 Codex 进程的移动／缩放事件；漏掉结束通知时检查原生移动状态并恢复。关闭兼容模式、正常停止控制器时也会恢复由它收起的宠物。纯命令行启动不启用 Windows 原生事件监听，仍可使用左侧位置或手动隐藏。这是兼容处理，拖动期间宠物短暂不可见，底层问题仍待解决。

修订使用已核对的宠物原生窗口进行快速收起，并预热本机连接，降低收起延迟。初版和快速收起修订的本机实测均为：开头仍短暂闪烁，随后拖动顺畅，松手恢复正常。尚未完全解决起步阶段。

## 手动绕法

1. 保持大肥鱼显示，把它拖到屏幕最左侧边缘。只向左挪少量距离可能不够。
2. 把 Codex 调成普通窗口，在屏幕中央拖动，确认是否顺畅。
3. 如果左侧位置仍有问题，先从 Codex 收起整个宠物窗口，再移动主窗口，之后重新显示宠物。

助手的“恢复原宠物”会恢复原图，但原生宠物窗口仍在运行。它与完全隐藏宠物是两种不同的测试条件。

## 本机已验证的结果

2026-10-31，在官方 Windows 包 `26.1027.3384.0`、助手 v0.4.1 上完成了以下对照，同一 Codex 进程持续运行：

| 条件 | 用户观察 |
| --- | --- |
| 大肥鱼显示在右侧 | 主窗口拖动时跳动 |
| 完全隐藏宠物窗口 | 拖动顺畅 |
| 大肥鱼保持显示并放到屏幕最左侧 | 拖动顺畅 |

前两轮同时采集了主窗口位置、尺寸和鼠标位置。剔除宽高改变的相邻采样后，显示宠物的一轮仍捕获多次约 1280 像素的横向跳变，与宠物透明窗口的横向起点相符；隐藏的一轮没有同类跳变。这里记录的是有限采样结果，不是动画帧率、完整事件计数或每台电脑的效果保证。左侧位置的验证来自用户实际拖动反馈。

## 目前能确认什么

本机现象与原生宠物叠层的显示、位置相关，证据支持跨窗口鼠标坐标干扰的判断。尚未追踪运行时具体采用的鼠标转发或输入形状分支，不能断言某个内部调用就是根因。

[OpenAI 官方仓库 #53273](https://github.com/openai/codex/issues/53273) 有高度匹配的反馈，包含隐藏／显示、左右位置对照及原生窗口坐标记录。相关的 [Electron #35030](https://github.com/electron/electron/issues/35030) 可作为排查线索，但不能据此认定当前 Codex 原生运行时的具体实现相同。

这是保留宠物显示的位置绕法。底层问题仍待解决，拖回右侧可能再次出现。另一台电脑需要单独验证。
